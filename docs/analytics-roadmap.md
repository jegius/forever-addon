# Analytics roadmap and code-review findings

Этот документ — карта улучшений ForeverAddon: найденные проблемные места, приоритеты и безопасная
архитектура ИИ-советника. Цель — **легальный аналитический помощник**, без автокликов, чтения экрана
и управления персонажем.

## 1. Что уже работает

- Browse-скан аукциона, детальный скан лотов, история цен.
- Флипы с учётом 5% комиссии и фильтром выбросов.
- Каталог рецептов всех профессий, компоненты, цепочки «крафт → DE → продажа».
- Рейтинг профессий, лучшие зоны фарма трав/руды из GatherMate2, рейтинг кожи по видам.
- Popup-подсказка с медианой, минимумом, объёмом и предупреждением о демпинге.

## 2. Проблемные места (по приоритетам)

### P1 — качество данных и покрытие цен

1. **Цепочки строятся только при полном наборе цен на все реагенты.**
   У большинства профессий часть предметов не сканируется, поэтому видны только Алхимия/Наложение
   чар. Это не баг рейтинга, но выглядит как баг.
   - Решение: показывать `coverage = priced / total`, кнопку «докачать цены», приоритет запросов
     по ожидаемой прибыли, а не по порядку каталога.
2. **Разные источники цены.**
   В флипах используется `resale`/медиана, в цепочках реагенты берутся по `min`, выход — по
   `median`. Один и тот же предмет может оцениваться по-разному.
   - Решение: единый `PriceService`: `median`, `p25`, `p75`, `min`, `max`, `volume`,
     `samples`, `deviation`, `confidence`.
3. **Медиана по 7 дням без веса по объёму.**
   Один лот на 1 шт может перекосить медиану.
   - Решение: volume-weighted median, MAD (median absolute deviation), минимальный объём для
     рекомендации.
4. **DE-таблица Classic только до ilvl 65.**
   Для кастомных предметов Forever ilvl/качество может отсутствовать; fallback «ближайший
   диапазон» приблизителен.
   - Решение: кэш item metadata (ilvl/quality/class) в SavedVariables, отдельная таблица для
     кастомных предметов, явный флаг `estimated`, показывать `—` вместо 0.
5. **Нет учёта депозита, срока выставления и скорости продаж.**
   Прибыль считается как будто всё продастся мгновенно.
   - Решение: `expected_profit = profit * sale_probability - deposit`, где
     `sale_probability` оценивается по исчезновению лотов/истории продаж.
6. **Статический каталог — снимок.**
   Рецепты/цены могут устареть после патча.
   - Решение: версия каталога в UI, проверка `build`, возможность обновить `Catalog.lua`
     отдельным генератором.

### P1 — аналитика фарма

7. **Зоны фарма = число узлов × цена, без времени и конкуренции.**
   Нет учёта респавна, yield, времени в пути, конкурентов, фазы.
   - Решение: `score = nodes * yield * price / (respawn + travel)`, где параметры
     настраиваются; показывать «потенциал/час» с диапазоном.
8. **Кожа без зон.**
   GatherMate2 не хранит skinning-мобов.
   - Решение: подключаемый источник «зона → виды мобов → кожа» (ручной JSON/датасет), либо
     честно оставить рейтинг видов и не выдавать зоны.
9. **Нет истории фарма.**
   Сессия не записывается, нельзя сравнить «до/после».
   - Решение: `FarmingSession` (старт/стоп, улов/добыча, время, зона, золото/час).

### P2 — UI/UX и производительность

10. **Каталог 2000+ рецептов без поиска/фильтров.** Есть сортировка, но нет фильтра по профессии,
    skill, прибыли, покрытию.
11. **Тяжёлые пересчёты.** `GetCatalogChains` перебирает весь каталог; кэш есть, но при каждом
    изменении цены всё пересчитывается. Нужен инкрементальный кэш по itemID.
12. **Смешанные единицы.** Медь/золото/серебро и проценты — нужен единый форматтер и
    настройка «показывать в gold/silver».
13. **Подсказки перегружены.** Chain tooltip длинный; нужен компактный режим и «подробнее».
14. **Ошибки загрузки.** Многие инициализации обёрнуты в pcall; нужен видимый debug-лог
    (`/fa debug`) с кольцевым буфером.

### P2 — инженерия

15. **Нет CI/юнит-тестов в репозитории.** Есть только внешний mock-харнесс.
    - Добавить `tests/` с Lua-моками, GitHub Actions: синтаксис (`luac`/luaparse), unit-тесты
      `Market`, `Disenchant`, `Recipes`.
16. **Нет версионирования схемы SavedVariables.**
    - `db.schemaVersion`, миграции, `backup` при несовместимости.
17. **Нет ограничения размера SavedVariables.**
    - Сжатие истории (30 дней), pruning, оценка размера.
18. **Локализация.** Часть строк захардкожена, каталог на английском.
    - Все строки в Locales; локализация названий через `C_Spell.GetSpellInfo`.

## 3. Безопасный ИИ-советник (архитектура)

### Принципы

- ИИ **не управляет игрой**: нет кликов, ввода, чтения экрана, памяти.
- ИИ получает только **снимок данных**, который аддон уже сохранил.
- Ответы ИИ — рекомендации, а не команды; пользователь сам решает и действует.
- Локальный режим по умолчанию; никаких API-ключей в аддоне.

### Схема

```text
WoW addon (Lua)
  → SavedVariables (ForeverAddonDB.lua)
  → экспорт компактного JSON (items, prices, history, recipes, coverage)
  → локальный MCP-сервер / агент (вне игры)
  → отчёт: топ флипов, цепочки, риски, чего не хватает
```

Экспорт можно делать отдельным скриптом/MCP-инструментом; **аддон не делает HTTP-запросов**.

### Инструменты агента

- `market_health`: свежесть, покрытие, аномалии.
- `top_flips`: прибыль, ROI, confidence, риск.
- `craft_plan`: что купить/скрафтить/продать, с учётом капитала.
- `profession_advice`: какую профессию качать под текущий рынок.
- `farming_plan`: зоны/ресурсы, ожидаемый доход/час.
- `explain`: почему рекомендация, какие данные, какие допущения.

### Guardrails

- Никаких «гарантированных» прибылей; всегда диапазон и confidence.
- Явно помечать: мало истории, мало лотов, возможный демпинг, неполные цены.
- Не рекомендовать покупать весь рынок/дорогие лоты без проверки.
- Не давать инструкции по автоматизации, обходу античита, мультибоксингу.
- Не отправлять персональные данные; только агрегированные цены.

### Фазы

1. **Сейчас:** rule-based рейтинги + coverage + риск-флаги (без ИИ).
2. **Далее:** экспорт JSON + MCP-инструменты; локальная LLM формирует текстовый отчёт.
3. **Потом:** диалоговый советник («у меня 500g, что делать?») с бюджетом и ограничениями.
4. **Опционально:** сравнение нескольких сканов/дней, алерты об изменениях (вне игры).

## 4. Приоритетный план

1. Единый `PriceService` + volume-weighted median + MAD.
2. Coverage/приоритетное докачивание цен.
3. Item metadata cache (ilvl/quality/class) и точный DE.
4. Учёт депозита/скорости продаж.
5. Фильтры/поиск в UI, компактные подсказки.
6. Тесты + CI + schemaVersion.
7. JSON-экспорт и MCP-советник.

## 5. Что не делать

- Автоклики, чтение пикселей, эмуляция ввода, обход Warden.
- «Гарантированные» стратегии и обещания дохода.
- Сбор персональных данных или API-ключей в аддоне.
