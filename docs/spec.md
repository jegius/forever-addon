# ForeverAddon — спецификация

**Версия:** 0.1 (design) · **Дата:** 7 ноября 2026 · **Статус:** проектирование, код не реализован.

Аддон-помощник прокачки профессий для **World of Warcraft: Forever**: память найденных источников
ресурсов, эффективные маршруты, подсказки по добыче и прокачке, предупреждения об опасности и
переполнении сумок.

Ключевой принцип: **аддон информирует и навигирует, но не играет за игрока.** Это и техническое
ограничение клиента WoW, и требование политики Blizzard.

---

## 1. Что именно делает аддон

1. Запоминает узлы ресурсов: травы, руду/жилы, трупы животных для снятия кожи (и, при желании,
   сундуки/рыбу в следующих версиях).
2. Показывает узлы на карте и миникарте, с фильтрами по профессии, типу ресурса, зоне и свежести.
3. Строит маршрут по выбранным узлам (nearest-neighbor + 2-opt) и ведёт по нему стрелкой/HUD,
   выставляет waypoint (своя точка или TomTom).
4. Подсказывает, хватает ли навыка профессии для узла; предупреждает «навык мал» / «труп не
   снимается».
5. Предупреждает о заполнении сумок, подсказывает вендора/банк/отдых, предлагает депозит при
   открытом банке.
6. Показывает **оценку риска** у цели/узла (уровень, элитность, число врагов, экипировка) — только
   как подсказку, без автобоя.
7. Помогает с планом прокачки профессии: какие узлы/рецепты нужны на текущем навыке, где их искать.
8. Экспорт/импорт узлов и маршрутов; опционально — внешний планировщик с локальным ИИ.

## 2. Термины и допущения

- **Узел** — игровой объект/труп, с которого добывается ресурс: `herb`, `ore`, `skin` (позже — `chest`,
  `fish`).
- **Профессия** — `Herbalism`, `Mining`, `Skinning` (добывающие); крафтовые — в плане прокачки.
- **MVP** — версия 0.1: память узлов, карта, фильтры, экспорт/импорт.
- Целевой клиент: `_forever_`, TOC `## Interface: 16001`, билд `1.60.1.70790`.
  API — Mainline 12.1.5 + ограничения Midnight (secret values, нет combat log, ауры в бою недоступны).

## 3. Границы: что технически возможно

### 3.1 Автоматизация игрового процесса невозможна

Проверено по API и политике Blizzard (подробности — [docs/research.md](research.md)):

| Действие | Вердикт | Причина |
| --- | --- | --- |
| Движение персонажа | ❌ | `MoveForwardStart`, `TurnLeftStart`, `JumpOrAscendStart` — protected + hardware event |
| Каст/применение предметов | ❌ | `CastSpellByName`, `UseAction`, `C_Container.UseContainerItem` — protected |
| Взаимодействие с узлом/трупом | ❌ | `InteractUnit` отсутствует в 12.1.5; взаимодействие — клиентское |
| Авто-лут после открытия окна | ⚠️ | `LootSlot` не protected, но окно открывается только действием игрока; это автоматизация |
| Авто-бой | ❌ | `TargetUnit`, `RunMacro`, `StartAttack` — protected/автоматизация |
| Авто-выход из игры | ❌ | `Logout()`/`Quit()` protected с 7.3.2 |
| Движение по маршруту | ❌ | нет API управления движением; только waypoint/стрелка |
| Чтение памяти, инъекции, эмуляция ввода | ❌ | запрещено EULA; бан |

Blizzard: addon не должен давать преимущество в бою и не может автоматизировать действия
([UI Add-On Development Policy](https://us.forums.blizzard.com/en/wow/t/ui-add-on-development-policy/24534),
[EULA/cheating](https://us.forums.blizzard.com/en/wow/t/prohibitions-on-third-party-software/2142972)).
Поэтому «автоматическая добыча», «авто-бой» и «авто-логаут» в проект **не входят** — это бот, а не
аддон.

### 3.1.1 Чем грозит внешняя автоматизация

Внутри аддона автоматизировать игровой процесс нельзя, но **вне** клиента можно запустить стороннюю
программу (эмулятор ввода, кликер, «пиксельный» бот, чтение памяти, инъекция). Это уже не аддон, а
читерское ПО:

- нарушение EULA/политики Blizzard: запрещено ПО, которое «изменяет и/или облегчает игровой
  процесс» без разрешения Blizzard;
- античит Blizzard (Warden) и серверная аналитика видят повторяющиеся паттерны, аномальное время
  сессий, идеальные маршруты и реакции; плюс жалобы игроков;
- последствия — от предупреждения до **бессрочной блокировки аккаунта**, удаления достижений/предметов
  и блокировки по железу; апелляции по таким банам обычно не удовлетворяют;
- «безопасной» автоматизации не существует: платные боты тоже попадают в волны банов, а
  рандомизация задержек не делает поведение неотличимым от человека;
- даже простой автокликер/макрос-луп — уже автоматизация, а не «просто удобство».

Вывод: **автоматизировать добычу/бой/выход нельзя без риска потерять аккаунт.** Проект не будет
содержать и не будет подсказывать, как обходить эти ограничения.

### 3.1.2 Что разрешено и как ускорить процесс легально

- Встроенные возможности игры: автолут в настройках, клавиша взаимодействия, макросы (одно нажатие —
  одно действие, без циклов).
- Аддоны-навигаторы и планировщики: GatherMate2, Routes, TomTom, HandyNotes, TSM/CraftSim — они
  показывают и считают, но действия выполняет игрок.
- Внешний планировщик, который **не взаимодействует с клиентом**: читает экспорт/SavedVariables,
  считает маршрут, отдаёт import-строку. Это просто расчёты, а не бот.
- Наш аддон: память узлов, маршрут, HUD-стрелка, проверка навыка, риск-скор, сумки/банк — всё
  сокращает время принятия решений и беготню, не нарушая правила.

### 3.2 Как требования пользователя преобразуются в фичи

| Исходное требование | Что реально можно | Что делаем |
| --- | --- | --- |
| Запоминать трупы/травы/жилы | ✅ | собственный DB узлов + пины на карте |
| Строить маршруты между узлами | ✅ (навигация) | NN + 2-opt, линия на карте, HUD-стрелка, waypoint |
| Автоматически добывать | ❌ | подсветка/подсказка «добывай здесь», без нажатий за игрока |
| Выход из игры при полных сумках | ❌ (`Logout` protected) | предупреждение + подсказка вендор/банк/отдых + готовый `/logout`-макрос |
| Авто-склад в банк | ⚠️ частично | кнопка «депозит» при **открытом** банке (`C_Bank.AutoDepositItemsIntoBank`), без перемещения |
| Оценка боя «90% победы» | ❌ (секретные HP, нет combat log) | эвристическая шкала риска low/medium/high, решение за игроком |
| Добывать только доступные ресурсы | ⚠️ частично | фильтр/подсказка по навыку из БД + тултипа; серверное ограничение не запрашивается |
| Помощь в прокачке профессий | ✅ | план по навыкам/узлам, позже — рецепты и материалы |

## 4. Пользовательские сценарии

1. **Сбор и память.** Игрок собирает траву/руду/снимает кожу. Аддон по событию каста и подтверждению
   лута записывает имя ресурса, тип, профессию, карту, координаты, время и персонажа. Узел появляется
   на карте.
2. **Маршрут.** Игрок выбирает профессию, зону и типы ресурсов. Аддон строит порядок обхода, рисует
   линию и ведёт стрелкой к следующему узлу. Игрок сам решает, идти ли туда.
3. **Опасность.** Возле элитного моба/группы мобов аддон показывает риск и советует обойти; авто-боя
   нет.
4. **Сумки.** Свободных слотов меньше порога — предупреждение, подсказка ближайшего известного
   вендора/банка/отдыха, кнопка «депозит» при открытом банке.
5. **Прокачка.** Для текущего навыка показывается, какие ресурсы/узлы нужны и в каких зонах их
   искать; после — план крафта (v0.3+).
6. **Обмен.** Экспорт узлов/маршрута строкой; импорт на другом персонаже/аккаунте; опционально —
   внешний планировщик.

## 5. Функциональные требования по версиям

### MVP (v0.1)

- DB узлов в SavedVariables; запись из событий; ручное добавление (`/fa add`).
- Пины на мировой карте и миникарте; тултип узла (тип, профессия, когда найден, персонаж).
- Фильтры: профессия, тип ресурса, зона, «только мои», давность.
- Список узлов, удаление/очистка, счетчик.
- Экспорт/импорт строкой (Base64 + сериализация).
- Настройки (порог сумок, фильтры, звук), slash-команды, локализация ruRU/enUS.
- Защита от секретных значений: любые строки тултипов/имена юнитов перед показом и сравнением
  проверяются `issecretvalue`/`canaccessvalue` (где доступно).

### v0.2 — маршруты и навигация

- Построение маршрута по выбранным узлам: nearest-neighbor + 2-opt, ограничение по количеству.
- Линия маршрута на карте (оверлеи), нумерация точек, HUD-стрелка «следующий узел» + расстояние.
- Прогресс: узел считается посещённым при подходе/сборе, автопереход к следующему.
- Интеграция с TomTom (если установлен) и `C_Map.SetUserWaypoint`; учитывать protected-вызовы в бою.
- Сохранение/загрузка именованных маршрутов.

### v0.3 — профессии и опасность

- Данные требований по навыку для узлов (классический Азерот, 1–300): таблица `Data/SkillReq.lua`.
- Определение своего навыка: `GetProfessions()` + `GetProfessionInfo(index)`; обновление по
  `SKILL_LINES_CHANGED`/`PLAYER_LOGIN`.
- Подсказка «навык мал» в тултипе узла; фильтр маршрута «только доступное».
- Danger score: разница уровней, элита/редкий, число врагов, ilvl, PvP-флаг; цветовая шкала и
  пояснение. Без чтения HP и без combat log.
- Банк: кнопка депозита при открытом банке (`C_Bank.CanUseBank`,
  `C_Bank.AutoDepositItemsIntoBank`), проверка на 70790.

### v0.4 — план прокачки профессии

- План по навыкам: «1–50 — Peacebloom/Silverleaf, 50–100 — Mageroyal…» с зонами и узлами.
- Для крафтовых профессий: рецепты, материалы, тренеры; данные из `C_TradeSkillUI` и справочника.
- Список материалов «докупить/дособрать», связка с узлами.
- Возможная интеграция с Ackis Recipe List Forever / ProfGuides вместо дублирования данных.

### v1.0 — companion + локальный ИИ (опционально)

- Python-приложение читает экспорт узлов/маршрута, решает TSP/VRP (OR-Tools), генерирует import-строку.
- Локальная LLM (Qwen3 4B/8B, Gemma 3 4B и т. п. через Ollama/LM Studio) — только для плана,
  объяснений и перевода целей в веса; **не** в цикле оптимизации.
- Никакого чтения памяти, инъекций и генерации ввода: только файлы/буфер обмена.

## 6. Данные

### 6.1 SavedVariables

```lua
ForeverAddonDB = {
  version = 1,
  settings = {
    bagThreshold = 3,
    minimap = true,
    sound = false,
    danger = true,
    locale = "ruRU",
  },
  nodes = {
    -- ключ: mapID .. ":" .. type .. ":" .. округлённые координаты
    ["2022:herb:0.523:0.418"] = {
      mapID = 2022,
      x = 0.523, y = 0.418,
      type = "herb",              -- herb | ore | skin | chest | fish
      name = "Peacebloom",        -- имя узла/моба
      profession = "Herbalism",   -- Herbalism | Mining | Skinning
      skill = 1,                  -- навык персонажа в момент сбора
      char = "Realm-Name",
      firstSeen = 1730000000,
      lastSeen = 1730000000,
      count = 1,
    },
  },
  routes = {
    ["Herbalism:Elwynn"] = { mapID = 2022, nodeKeys = { ... }, createdAt = ... },
  },
  chars = {
    ["Realm-Name"] = {
      professions = { Herbalism = 75, Mining = 1, Skinning = 0 },
    },
  },
}
```

- Ключ узла: `mapID:type:rounded(x,3):rounded(y,3)`; при записи — поиск ближайшего узла того же типа
  в радиусе (порог в нормализованных координатах, настраивается; ориентир — GatherMate2).
- Хранить не больше N узлов на карту (например, 2000), чистить старые/дубли.
- Миграции по `version` при `ADDON_LOADED`.

### 6.2 Сбор данных

- `UNIT_SPELLCAST_SENT(unit, target, castGUID, spellID)` — начало сбора; `target` = имя узла/моба.
- `UNIT_SPELLCAST_STOP` / `UNIT_SPELLCAST_FAILED` — отмена кандидата.
- `UNIT_SPELLCAST_SUCCEEDED` — подтверждение (spellID Mining/Herbalism/Skinning).
- `LOOT_OPENED` + `GetLootSourceInfo(slot)` — альтернативное подтверждение и GUID GameObject
  (проверить на 70790).
- `CURSOR_CHANGED` — курсор «сбор/снятие кожи» (проверить).
- `UI_ERROR_MESSAGE` — сообщения «Requires …» / «навык слишком мал» (проверить текст).
- Позиция: `C_Map.GetBestMapForUnit("player")` + `C_Map.GetPlayerMapPosition(mapID, "player")`.
  **Только открытый мир**: в подземельях/рейдах/полях боя позиция `nil` (`#noinstance`), узлы там не
  записываем.
- Тип ресурса: по профессии/заклинанию + статическая таблица имён; для кожи — по мобу.

## 7. Архитектура

### 7.1 Файлы (порядок в TOC)

```text
ForeverAddon/
├── ForeverAddon.toc
├── Locales/enUS.lua
├── Locales/ruRU.lua
├── Core.lua            -- namespace, события, инициализация, slash
├── DB.lua              -- SavedVariables, миграции
├── Nodes.lua           -- запись/дедуп/запросы узлов
├── Map.lua             -- пины на мировой карте и миникарте
├── Routes.lua          -- построение/хранение маршрутов
├── HUD.lua             -- стрелка, следующий узел, прогресс
├── Professions.lua     -- навыки, требования, «доступность»
├── Danger.lua          -- эвристика риска
├── Bags.lua            -- свободные слоты, предупреждения, банк
├── ImportExport.lua    -- сериализация/Base64/импорт
├── Options.lua         -- настройки
└── Data/SkillReq.lua   -- таблица требований по навыку (v0.3)
```

Каждый файл: `local addonName, ns = ...`; общее состояние — на `ns`. Глобалы: только SavedVariables,
`SLASH_*`/`SlashCmdList`, колбэки из TOC.

### 7.2 Модули и ответственность

- **Core** — `ADDON_LOADED`, `PLAYER_LOGIN`, `PLAYER_ENTERING_WORLD`, `ZONE_CHANGED_NEW_AREA`;
  регистрация событий; `ns:Print`, `ns:Debug`.
- **DB** — инициализация/миграция `ForeverAddonDB`, настройки по умолчанию.
- **Nodes** — кандидат → подтверждение → запись; дедуп; выборки по карте/профессии/типу.
- **Map** — пины: `WorldMapFrame`/`C_Map` координаты → позиция фрейма; миникарта; тултипы; фильтры.
- **Routes** — матрица расстояний, NN + 2-opt, сохранение; лимит узлов (например, 300).
- **HUD** — стрелка к следующему узлу (по `GetPlayerFacing`/позиции), расстояние, статус.
- **Professions** — `GetProfessions`/`GetProfessionInfo`, кэш навыков, проверка требований.
- **Danger** — score по цели/окружению; без HP/CLEU.
- **Bags** — `C_Container.CalculateTotalNumberOfFreeBagSlots()`, порог, банк.
- **ImportExport** — строка `FA1:` + Base64; копируемый EditBox; валидация.
- **Options** — панель настроек (сначала простая, без Ace3; Ace3 — опционально позже).

### 7.3 События

`ADDON_LOADED`, `PLAYER_LOGIN`, `PLAYER_ENTERING_WORLD`, `ZONE_CHANGED_NEW_AREA`,
`UNIT_SPELLCAST_SENT`, `UNIT_SPELLCAST_SUCCEEDED`, `UNIT_SPELLCAST_STOP`, `UNIT_SPELLCAST_FAILED`,
`LOOT_OPENED`, `CURSOR_CHANGED`, `UI_ERROR_MESSAGE`, `BAG_UPDATE_DELAYED`, `BANKFRAME_OPENED`,
`BANKFRAME_CLOSED`, `PLAYER_REGEN_DISABLED`, `PLAYER_REGEN_ENABLED`, `UNIT_THREAT_SITUATION_UPDATE`,
`SKILL_LINES_CHANGED`.

Все обращения к защищённым API — только вне `InCombatLockdown()`; в бою UI обновляется без вызовов,
запрещённых в бою.

### 7.4 Производительность

- Индексы узлов: `byMap[mapID][type] = { keys }`, `byProfession[prof][mapID]`.
- Пины создаются лениво, только для видимой карты; лимит одновременных пинов.
- Дедуп O(1) по ключу + локальный поиск в сетке (grid) для соседних узлов.
- SavedVariables: компактные ключи, только координаты/имя/тип/время; без тяжёлых таблиц.

## 8. Алгоритмы

### 8.1 Маршрут

1. Вход: `mapID`, профессия, типы, «только доступные», стартовая позиция.
2. Матрица расстояний в нормализованных координатах карты; для сортировки этого достаточно,
   для отображения расстояния в ярдах — приближение (масштаб карты).
3. Nearest-neighbor от старта, затем 2-opt до улучшения (≤300 узлов — быстро).
4. Опционально: кластеризация по зонам/подзонам, ограничение времени.
5. Сохранить порядок; при сборе/подходе отмечать посещённые; пересчёт по кнопке.

### 8.2 Риск (danger score)

Эвристика (без HP, без combat log):

```text
score = 0
score += clamp(mobLevel - playerLevel, -3, 5) * 10
score += elite and 30 or 0
score += rare and 15 or 0
score += max(0, enemyCount - 1) * 8
score += PvP-flag и enemyPlayer and 40 or 0
score += (playerIlvl ниже ожидаемого для уровня) and 10 or 0
```

`low < 20`, `medium 20–49`, `high ≥ 50`. Показывать как индикатор/тултип, не блокировать и не
автоматизировать. Точная вероятность победы невозможна: HP не-игроков — secret, combat log недоступен.

### 8.3 Сумки и банк

- Свободные слоты: `C_Container.CalculateTotalNumberOfFreeBagSlots()` +
  `C_Container.GetContainerNumFreeSlots(bag)`; порог по умолчанию 3.
- Предупреждение в чат + HUD; если `IsResting()` — подсказка «можно /logout», иначе «вернись в
  город/к вендору». `Logout()` аддон вызвать не может (protected) — только готовый макрос.
- Банк: при `BANKFRAME_OPENED` и `C_Bank.CanUseBank` — кнопка «депозит» →
  `C_Bank.AutoDepositItemsIntoBank(bankType)`. Только при открытом банке; без перемещения.

### 8.4 Доступность ресурса

- Свой навык: `GetProfessions()` + `GetProfessionInfo(index)` (skillLevel/maxSkillLevel).
- Требование узла: статическая таблица (v0.3) + попытка прочитать тултип:
  `C_TooltipInfo.GetWorldCursor()` / `C_TooltipInfo.GetWorldLootObject("mouseover")` — искать
  «Requires Herbalism/Mining (X)» (проверить на 70790; строки могут быть secret).
- Для кожи: отдельного API «можно ли снять» нет; ориентир — курсор/тултип трупа (проверить).
- Итог: подсказка/фильтр; окончательное решение — за игроком.

## 9. UI

- **Мировая карта:** пины узлов (цвет по профессии), фильтр-панель, кнопка «маршрут», линия маршрута,
  номера точек.
- **Миникарта:** маленькие точки/иконки, переключатель.
- **HUD:** компас-стрелка, «следующий узел: Peacebloom, 42 м», прогресс `3/25`.
- **Окно аддона:** вкладки «Узлы», «Маршрут», «Профессии», «Настройки» (простая панель).
- **Тултипы:** тип, имя, профессия, навык, когда найден, персонаж.
- **Сумки:** индикатор свободных слотов, предупреждение, кнопка депозита (банк).
- Стиль: светлый/тёмный, ruRU/enUS, шрифты Blizzard; без внешних текстур в MVP.

## 10. Companion + локальный ИИ (v1.0, опционально)

- Аддон не имеет доступа к сети/файлам/ОС. Каналы: SavedVariables (при закрытой игре) и
  экспорт/импорт строкой (буфер обмена).
- **Python-планировщик:** читает экспорт, строит TSP/VRP (OR-Tools или networkx), учитывает
  профессию, доступность, вместимость сумок, риск; выдаёт import-строку.
- **LLM (Qwen3 4B/8B, Gemma 3 4B, аналоги):** только для плана прокачки, объяснений, перевода
  «хочу качать травничество в Элвинне» в параметры. Маршруты — детерминированный алгоритм.
- **Железо на этой машине:** i5-14600KF, 64 ГБ RAM, RTX 4070 Ti 12 ГБ — 4B/8B в Q4 комфортно;
  Ollama/LM Studio/llama.cpp. Сейчас локальный рантайм не установлен.
- **ToS:** никакого чтения памяти, инъекций, эмуляции ввода; только файлы/буфер обмена.

## 11. Лицензии и данные

- Код — предлагается MIT (решение за автором).
- Не бандлить координаты из Wowhead/GatherMate2_Data: у данных нет свободной лицензии.
- Импорт **из установленного** GatherMate2 (чтение его SavedVariables) допустим как опция
  совместимости; код GatherMate2 (GPL-2.0+) не копировать.
- Свои узлы — только собранные игроком.
- Forever-специфичные карты узлов есть на сторонних сайтах, но без лицензии/API — не используем без
  разрешения.

## 12. Тестирование на 70790

1. Запись травы/руды/кожи в открытом мире; проверка SavedVariables после `/reload`.
2. Отсутствие записи в подземельях/рейдах/БГ (позиция `nil`).
3. Дедуп: повторный сбор того же узла не создаёт дубль.
4. Пины на карте/миникарте, фильтры, тултипы.
5. Маршрут: корректный порядок, линия, HUD-стрелка; защита в бою (`InCombatLockdown`).
6. Проверка тултипа «Requires …»; `C_TooltipInfo` и секретные строки.
7. Свободные слоты и предупреждение; `C_Bank.AutoDepositItemsIntoBank` при открытом банке.
8. `Logout()` из аддона недоступен — убедиться, что нет taint/ошибок.
9. `UnitHealth`/`UnitClassification`/`UnitLevel` на 70790; риск-скор без секретов.
10. `C_Map.SetUserWaypoint`/`C_SuperTrack` в бою и вне боя; TomTom.
11. Производительность: 1000+ узлов, открытие карты, `/reload`.
12. Совместимость с GatherMate2/TomTom (не конфликтовать).

## 15. Fishing assistant (опционально, compliant)

Рыбалка — отдельный кейс: автоматизировать её нельзя (см. [docs/fishing-automation.md](fishing-automation.md)),
но можно сделать легальный помощник:

- статистика сессии: забросы, улов, рыба/мусор, улов в час, зона, время;
- журнал и экспорт для анализа (локальная LLM — после сессии);
- счётчик свободных слотов + предупреждение «сумки полны»;
- напоминание `/logout` и `IsResting()`; таймер с момента заброса (без детекта поклёвки);
- память мест/косяков; подсказки по навыку и зонам.

Реализация — отдельный модуль `Fishing.lua` (v0.5), без автозабросов, автокликов и автовыхода.
Никаких внешних программ, эмулирующих ввод.

## 16. Auction module (implemented in v0.4.0)

Реализованный модуль заработка на аукционе:

- **Скан:** `C_AuctionHouse.SendBrowseQuery` с пустым поиском; страницы через
  `AUCTION_HOUSE_BROWSE_RESULTS_ADDED` + `RequestMoreBrowseResults`; обработка
  `AUCTION_HOUSE_BROWSE_RESULTS_UPDATED`; сохранение в `ForeverAddonDB`.
- **Данные:** `BrowseResultInfo{itemKey, minPrice, totalQuantity}`; минимальная цена и объём по
  `itemID`, дневная история `{min, qty, n}` + последние 20 сэмплов, `itemNames`.
- **Детальный скан:** после browse — `SendSearchQuery` по 60 товарам/реагентам и до 20 предметам
  экипировки (ключ `itemID + itemLevel + itemSuffix`), лестницы цен, `HasFull*` + `RequestMore*`,
  лимит ~75 запросов/мин.
- **Флипы:** detail — покупка дешёвого лота → `resale` (следующий уровень) → прибыль после 5%,
  ROI, confidence; плюс старые флипы по истории/сэмплам. Работают с одного скана.
- **Экипировка:** варианты агрегируются по базовому `itemID`, detail — по ключу самого дешёвого
  варианта; порог `gearMinPrice`.
- **График:** дневная история или точки сканов/детального скана; 30 дней.
- **Рецепты:** `GetAllRecipeIDs` + fallback `GetProfessionSpells`, `GetRecipeSchematic`, стоимость
  реагентов, выход, прибыль; рецепты без цены показываются и докачиваются детальным сканом (до 50).
- **Фарм:** группировка trade goods по subclass, оценка `market * (1 + log(qty+1))`; без зон/координат.
- **Ограничения:** депозит/истечение лота не моделируются; для экипировки сканируется только самый
  дешёвый вариант; нет TSM-данных и истории продаж.

Файлы: `Locales.lua`, `DB.lua`, `Util.lua`, `Market.lua`, `Auction.lua`, `Recipes.lua`,
`Charts.lua`, `UI.lua`, `Core.lua`. Тестирование в клиенте — по чек-листу [README.md](../README.md).
